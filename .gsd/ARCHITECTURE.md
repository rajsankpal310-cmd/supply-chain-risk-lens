## Overview

**NEXUS-CFR** (Nexus Risk Navigator / Supply Chain Risk Lens) is a comprehensive, data-driven financial risk prediction and supply chain resilience platform tailored for Small and Medium Enterprises (SMEs).

It bridges the gap between transactional SME accounts receivable/payable data (invoices, payments, buyer/supplier relationships) and systemic supply chain stress. It detects cascading payment delays, predicts default and cash-flow bottlenecks, discovers multi-tier network dependencies, resolves structural invoice deadlocks (circular debt), and recommends actionable financial interventions.

## Data Flow

1. **Ingestion Flow**:
   - User uploads invoice data (CSV/XLSX) via `UploadPage` or an ERP connector triggers scheduled sync.
   - Request enters `server/src/routes/upload.routes.ts` or `connector.routes.ts`.
   - `universalMappingEngine` normalizes schema fields into the canonical contract (`canonicalContract.ts`).
   - `businessValidator` and `duplicateDetector` validate records; defective rows are routed to `quarantineService`.
   - Valid records are committed to Prisma (`Transaction`, `Firm`, `Relationship`).

2. **Analysis & Prediction Flow**:
   - `server/src/ml/pipeline` triggers feature extraction and risk scoring.
   - Models compute counterparty risk, late-payment risk, and contagion indices.
   - Predictions and alerts are written to `Prediction` and `Alert` tables.

3. **Simulation & Optimization Flow**:
   - User configures scenario parameters on `SimulatorPage`.
   - `simulation.service.ts` runs stress propagation across the relationship graph.
   - Deadlock detection analyzes directed debt graph for circular dependency resolution.
   - Results are persisted to `SimulationRun` and `Deadlock`, then rendered on the frontend.

## Technical Debt & Observations

- [ ] **Dual Database Dialect Awareness**: Prisma schema specifies `postgresql` (`Supabase`), while local test environments and seeds have utilized SQLite (`dev.db`). Ensure migration paths and raw queries remain compatible or strictly partitioned.
- [ ] **Frontend Mock vs. Live REST Toggle**: While `client.ts` supports both, ensure complete parity between frontend mock data contracts and the Express API responses across all edge cases.
- [ ] **Large File Upload Worker Offloading**: 100MB+ file uploads currently process within Express thread via `controlledFileIngestionService`. High-volume production will benefit from background queue workers (BullMQ / Redis).
- [ ] **GSD Milestone Synchronization**: The repository has completed implementations through historical Phase 16, but `.gsd/` metadata files (`SPEC.md`, `ROADMAP.md`, `STATE.md`) were never formalized.
